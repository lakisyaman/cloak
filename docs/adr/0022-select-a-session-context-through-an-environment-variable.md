# Select a Session Context through an environment variable

A Shim will read `CLOAK_<CLI>_CONTEXT`, where `<CLI>` is the Managed CLI name in upper case with `-` changed to `_`, and use the named Context in place of the User-Global Active Context in `state.json`. Explicit Connection Input still wins and causes a Pass-through Invocation. A variable that names a missing Context fails closed and never falls back to `state.json`, because a silent fallback sends the command to the wrong target. Cloak's own variables are not Explicit Connection Input and are passed to the Real Command unchanged. We chose this because parallel agents and terminals share one `state.json`, so a `context switch` in one session silently changes the target of another; an environment variable exists only in its own process tree, like `AWS_PROFILE` or `KUBECONFIG`. This extends ADR 0003 without project-local selection, and the trade-off is a second selection source that users must notice, so the Invocation Notice and `context current` name the variable.
