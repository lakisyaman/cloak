# Load Connectors on demand from the repository registry

Cloak will replace its compiled, built-in Adapters with user-configurable Connector definitions interpreted by a generic runtime, allowing Managed CLI support to grow without a binary rebuild when definitions use supported runtime capabilities. Fresh installations will have zero registered Connectors; the Cloak repository will host a growing Connector Registry whose definitions are downloaded individually when users request them, with `mongosh`, `psql`, and `redis-cli` becoming optional definitions that preserve their existing Context Enrollment and Activation behavior. This trades a fixed, self-contained support set for extensibility and on-demand acquisition; Connector definitions will not be bundled with the binary.

Registration copies a definition into Cloak's internal per-user directory, and execution uses only that stored copy. This rule applies equally to registry downloads and user-supplied definitions: source changes take effect only after an explicit update copies the definition into Cloak again, keeping execution independent of source availability and subsequent edits. Schema version 1, explicit update/source replacement, and migration behavior are documented in the architecture and Connector schema.

The initial Connector format is declarative only; embedded scripts and executable hooks are deferred. The existing three Managed CLIs define the initial behavioral acceptance cases for the generic runtime, avoiding an executable extension API while requiring reusable capabilities that definitions can compose. New capabilities outside that vocabulary may require a runtime update.

Connector installation and update are independent of Context configuration, so changing a definition does not require collecting values for every existing Context. Validation against the installed definition happens when Activation is attempted; invalid Contexts fail closed with guidance to explicitly configure the affected Context. This permits definitions to evolve independently while making users resolve Context requirements at the point of use.
